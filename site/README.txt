WHOLE QUESTION — PUBLIC-SAFE STATIC DEMONSTRATION

Share THIS public package, not a project-root or private-study archive.
Open index.html in a modern browser. No installation, API key, account, database,
backend, or network access is needed for the interactive demo. The index file
contains its own code and fictional cases, so it can be sent on its own.

What it is: three authored fictional cases that change a bounded interpretation
and next step when evidence changes. It is deliberately not a live AI service,
psychological assessment, or scientific validation. Built with AI assistance
under Haley Bird's direction. Public browser source is visible by design.
No private chat, personal study, or proprietary project implementation is included.

PROOF.json contains hashes and exact test-scope declarations. Hashes can detect
byte changes; they do not establish inventorship, novelty, a trusted timestamp,
independent verification, or legal protection. Test assertions are authored by
the same implementation agent, not an independent auditor.

Reproduce public-package hashes and all 41 decision-rule tests (Python 3, Node 20+):
python verify.py

Portable smoke check (Node 20+):
node -e "const a=require('./engine.js'); if(!a.assess('release',['r2','r3']).title.includes('ready to transfer'))process.exit(1);console.log('smoke PASS')"

HOSTING (not completed by creating this package)
Use an already authorized static site. The existing Vercel route needs user
reauthentication. Do not create a paid plan or link an entire private repository.
For Vercel, deploy THIS directory as static files: no build command, output root '.',
no environment variables, no analytics. vercel.json carries security headers.
For hosts supporting _headers, use the supplied file; others need equivalent config.
Do not upload private/, tools/, raw chat exports, the predecessor, or the private ZIP.
Do not put secrets into this client-side application. There is no hidden server code.

LIVE ACCEPTANCE (still required after deployment)
1. Download live index.html and engine.js; compare SHA-256 with PROOF.json.
2. Check HTTPS and security headers (CSP, no-referrer, nosniff, DENY).
3. Exercise all three cases, individual evidence, reset, and JSON export.
4. Check desktop and phone; verify no automatic third-party requests.
5. Confirm host settings and logging are acceptable; retain the preceding deployment.
6. Record the live URL, release hashes, and executed test receipt. Only then call it deployed.

ROLLBACK
Redeploy the previous known-good public package or unpublish the site. A local
rollback folder is not a hosted rollback test. No domain, accounts, or credentials
were created by this build. No maintenance or background monitoring is active.
